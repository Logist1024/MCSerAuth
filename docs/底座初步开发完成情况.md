## 二、交付物完成情况

### 2.1 pnpm monorepo 脚手架

- 结构：`apps/web`（Next.js 16 App Router）+ `apps/server`（NestJS 12）+ `packages/shared`（类型单一事实来源）。
- 运行时基线：Node.js 22 LTS（`.nvmrc` 固定，`engines >=22`）、pnpm 9.15.9（`packageManager` 锁定）。
- **全仓 ESM**：NestJS 12 / drizzle-orm / better-auth 均为 ESM-only，server 采用 `"type": "module"` +
  NodeNext 解析，相对导入一律带 `.js` 后缀；TypeScript 固定 `~6.0.2`。

### 2.2 公共基建

| 能力       | 落地位置                                                  | 说明                                                                                             |
| ---------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| env 校验   | `apps/server/src/config/env.ts`                           | zod 一次性校验；生产强制 `BETTER_AUTH_SECRET`（≥32 字符、禁用开发默认值）与 `COOKIE_SECURE=true` |
| 统一错误码 | `packages/shared/src/errors.ts`                           | `{code:0,data}` / `{code,message}`；HTTP 状态 ↔ 业务码映射                                       |
| 异常过滤   | `common/filters/all-exceptions.filter.ts`                 | 统一信封与协议原生形状双轨分流                                                                   |
| DTO 校验   | 全局 `ValidationPipe` + class-validator DTO               | 协议端点错误名映射为 `IllegalArgumentException` 等                                               |
| 日志脱敏   | `common/logger/pino.config.ts` + `common/utils/redact.ts` | 令牌/Cookie/密码字段剔除，客户端 IP 掩码；dev 彩色、prod JSON                                    |
| 健康检查   | `GET /health`（排除 `/api` 前缀）                         | 进程 + SQLite 探活，未认证可访问                                                                 |

**信封分流机制**：Commons-Designs 端点经 `@ProtocolApi()` 打标，`ResponseInterceptor` 在请求对象上
写入 `PROTOCOL_REQUEST_MARKER`，异常过滤器据此决定输出 `{code,message}` 还是
`{error,errorMessage}`。（Nest 12 异常过滤器拿不到 handler 元数据，故采用请求打标方案；M1 协议
guard 需自行续打该标记。）

### 2.3 数据层

- SQLite + **WAL**、外键开启、`busy_timeout`（`db.service.ts` 连接参数显式设置）。
- Drizzle schema 共 **15 张表**（用户/账号、玩家与令牌、服务器白名单、皮肤披风、论坛帖子/回复/投票/
  举报/通知/审计日志），首版迁移 `apps/server/drizzle/0000_yielding_valeria_richards.sql` 已落库验证。
- 已定稿决策全部落库：S1 `player.user_id` UNIQUE、S2 `skin.kind` 区分皮肤/披风、
  S4 `player.nickname_history` JSON、S5 软删除（`token.revoked_at` 等）、S6 计数实时 COUNT、
  S3 权限为 `user.role` 枚举（无 RBAC 表）。
- **与临时指南的一处偏差（已决策）**：better-auth 三张表（session/account/verification）未采用
  "由其自动建表"，而是纳入 Drizzle schema 声明并随首版迁移一起生成——保证类型安全与事务一致性，
  迁移仍全部由 drizzle-kit 产出、禁止运行时同步。
- `pnpm db:migrate` 由自定义 `apps/server/scripts/migrate.mjs` 实现（自动建数据目录 + 开 WAL +
  执行 drizzle migrator），补足 drizzle-kit migrate 不建父目录的问题。

### 2.4 better-auth 接线

- 在 NestJS 侧接入（驱动 T3）：`/api/auth/*` 由 `toNodeHandler` 直接挂载在 JSON 解析器之前
  （保留原始 `req.url`），Nest `bodyParser` 关闭、其余路由手工 json/urlencoded 解析。
- 密码哈希采用 **argon2id**（项目安全基线，替代 better-auth 默认 scrypt）；`user.image` 映射
  既有 `avatar_url` 列；`role`/`banned`/`signature` 为 additionalFields（注册接口不可写）。
- Cookie 策略：本地 `Secure=false`，生产强制 `Secure/HttpOnly/SameSite=Lax`（env 校验兜底）。
- 冒烟结论：注册 200、登录 200、`get-session` 携带 Cookie 返回会话；库内账号凭证为
  `$argon2id$v=19$...`；错误密码 401。

### 2.5 API 契约

- Swagger UI `/docs`、OpenAPI JSON `/docs/json`，并产出 `docs/openapi.json`（13 路径 / 16 操作）。
- Commons-Designs 全部端点以 stub 登记，**协议原生形状**：

| 端点组                                                    | M0 行为                                               |
| --------------------------------------------------------- | ----------------------------------------------------- |
| `GET /api/oauth/availability`                             | 200 `{available:true}`                                |
| `GET /api/oauth/entry`                                    | 200 占位授权页 HTML（query 回显便于联调）             |
| `POST /api/oauth/authenticate` / `refresh`                | 501 `NotImplementedException`；缺参 400               |
| `GET /api/user/profiles/me`                               | 501                                                   |
| `POST /api/session/joinServer`                            | 501；三字段必填校验 400                               |
| `POST/GET /api/session/hasJoined`                         | 501；`username`/`serverId` 必填校验 400（双变体登记） |
| `/api/profiles/*`、`/api/minecraft/profile/{skins,capes}` | 501；批量接口数组校验 400                             |

- `docs/protocol-checklist.md` 首版成稿：逐端点请求/响应字段、状态码、错误名、M0 行为、
  待核对清单（6 项）与启动器联调记录模板。

## 四、开发期修复的缺陷

| #   | 问题                                                                                                 | 修复                                                             |
| --- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 1   | `POST /api/session/hasJoined` 误用 `@Query()` 读取参数，JSON body 校验必然失败                       | 改为 `@Body()`；验证：合法 body 得 501，缺参得 400               |
| 2   | OpenAPI 中 hasJoined GET 查询参数重复登记（显式 `@ApiQuery` 与自动推导并存）                         | 移除冗余装饰器；全文档校验无重复参数                             |
| 3   | pino 自定义请求序列化器收到的是已序列化对象（字段为 `remoteAddress` 等，而非原始 `IncomingMessage`） | 按 pino-std-serializers 输出字段重写                             |
| 4   | ESLint `consistent-type-imports` 对 NestJS `emitDecoratorMetadata`（`design:paramtypes`）误报        | 服务端关闭该规则并注明原因；另修正 3 处真实可改的 type-only 导入 |
| 5   | drizzle-kit migrate 不创建数据库父目录导致首跑失败                                                   | 改用 `scripts/migrate.mjs`（建目录 + WAL + migrator）            |
