# 生产可运营冲刺：本机生产预演 + F8 HTTP e2e 测试层

## Context

2.0 规划中 M5 已「代码侧完成」的 F3/F4/F5 都卡在真实 VPS（用户确认暂时没有），唯一 P0 的 F1（真机联调）按用户指示暂缓。因此当前把精力投向：
1. **本机能做的生产预演**——验证三产物可构建可启动、安全头/探针真实生效（GA 清单第 1 条的部分证据）；
2. **F8 HTTP e2e 测试层（M6 P1）**——关闭技术债 T4（supertest 已装未用），同时顺带关闭 F3.4（越权用例只有 service 级）和 F11 第 4 项（better-auth 挂载决策注释 + 错误格式一致性 e2e，即 T8）。

调研结论（已核实）：`@nestjs/testing` 不在 lockfile；现有测试完全绕过 Nest 容器；`main.ts` 的中间件链（better-auth 挂载在 body parser 之前、CSP、双 limiter）是 e2e 的关键价值，若用 `@nestjs/testing` 另起一套会复制这份顺序并必然漂移。

## 核心设计决策（写入 ADR 0008）

**e2e 形态：supertest + 复用真实 bootstrap 工厂，不引入 `@nestjs/testing`。**

1. **抽取共享启动工厂**：把 `apps/server/src/main.ts:26-110` 的装配逻辑（bodyParser:false、trust proxy、CORS、helmet、CSP nonce 中间件、双 express-rate-limit、better-auth handler 挂载、手动 json/urlencoded、setGlobalPrefix + `PREFIX_EXCLUDED_ROUTES`、swagger、shutdown hooks）抽到新文件 `apps/server/src/http/server.factory.ts`，导出 `createServerApp()`。`main.ts` 只剩：import + `createServerApp()` + listen + ready 日志。顺带在该文件的 better-auth 挂载处补 F11 要求的决策注释（为何绕过 Nest 管道、一致性靠哪条 e2e 守住）。
   - e2e 中 `const app = await createServerApp(); await app.init();` 然后对 `app.getHttpServer()` 跑 supertest——测试的中间件顺序与生产**逐字节一致**。
   - 不需要 overrideProvider：`MAIL_PROVIDER` 默认 console（只打日志不外呼）；captcha 在 `NODE_ENV=test` 下默认关闭（`captcha.service.ts:267`）。
2. **复用 `test/helpers/db.ts` 的 `createTestContext()`**（文件 SQLite 临时目录 + env 预设 + 迁移），每测试文件一次 beforeAll/afterAll（起 app 较贵，链路内共享状态）。不换 `:memory:`（迁移时机和 WAL 语义没必要动）。
3. **限流隔离不关限流**：`trust proxy=1` 下每个测试角色带独立 `X-Forwarded-For`，既避免 10/min credential limiter 串桶，又让链路 6 能真实测出 429。
4. vitest 配置零改动（`test/**/*.test.ts` 自动包含新目录，pool:forks、`TEST_DATABASE_URL` 直通 MySQL/PG 矩阵）；e2e 文件内 `vi.setConfig({ testTimeout: 60_000 })`。

### Phase 2：e2e 基建 helper
`apps/server/test/helpers/e2e.ts`：
- `createE2eContext()`：包 `createTestContext()` + `createServerApp()` + `app.init()`/`app.close()`；
- `registerVerifiedUser()`：POST `/api/auth/sign-up/email` → 从 `verification` 表取 token → GET `/api/auth/verify-email` → POST sign-in，返回带 cookie jar 与 `X-Forwarded-For` 的 actor；
- `promoteToRole()`：直接 `db.db.update(user).set({ role })`（session 每请求重读 user 行，改完即生效，参考 admin-access 既有用法）；
- `pngBuffer(width, height)`：用已安装的 sharp 生成合规纹理测试图。
